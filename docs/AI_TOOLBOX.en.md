# AI toolbox · How to read the tool names

**Status: November 23, 2026.** This is a project-based description, not a statement that every listed provider has a working production API integration.

## Evidence levels

| Level | Meaning |
|:--|:--|
| **A · Code reference** | An actual project module, client or API-related implementation exists. It is **not proof** of a deployed service. |
| **B · Development tool** | The tool is documented in project metadata, agent rules or build workflows. It may not be part of the end-user application. |
| **C · Planning/experiment** | A service or model is referred to in tasks or design documents, without a verified runtime integration. |

## AI assistants and APIs

| Technology | Level | Context |
|:--|:--|:--|

| Claude · Anthropic | **B** | Project records, agent instructions and development workflow documentation |

| OpenAI API | **B/C** | Architectural descriptions and dependency context, not a blanket runtime claim |

The supporting source repositories are intentionally **private**. These references describe inspected files and should not be confused with a public, independent audit.

## Design principle

**AI suggests → deterministic checks validate → humans approve → only then execute.** Real implementations differ by project and maturity.

To keep the portfolio trademark-conscious, this presentation uses **plain product names** and neutral custom SVG graphics rather than copied provider logos. No partnership, sponsorship or vendor certification is implied.
